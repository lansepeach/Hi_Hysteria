# 实时监控

更新脚本后运行 `hihy 17` 或 `hihy monitor`。首次进入会提示启用按 IP 统计；确认后重启正在运行的 Hysteria2 服务，客户端使用原密码重连。停止状态的服务保持停止。

```bash
hihy monitor enable    # 启用按 IP 统计，会重启正在运行的服务
hihy monitor           # 每 2 秒刷新，q 退出，j/k 滚动，g 回顶部
hihy monitor --once    # 输出完整单次快照，适合终端复制或重定向
hihy monitor disable   # 恢复 password 认证，会重启正在运行的服务
hihy monitor secure    # 仅迁移统计 API 的监听和密钥，保留认证方式
HIHY_MONITOR_INTERVAL=5 hihy monitor # 刷新间隔 1–60 秒
```

运行监控需要 Python 3 和 yq v4。新安装会自动安装依赖；旧安装若提示缺少 Python，请用发行版包管理器安装 `python3`（Arch 为 `python`）。建议使用 Hysteria v2.12.3 或更高版本。

菜单 13 也使用相同的 JSON 统计接口，读取实际 `trafficStats` 配置。它只输出一次快照，不启用或修改认证方式；使用原 password、userpass 或 HTTP 认证时仍可查看核心已有的统计标识。

## 可以看到什么

- 来源 IP 数、客户端连接数、活动 TCP 数；同一 IP 的多个客户端连接归为一组。
- 每个来源 IP 的累计上传/下载和实时速率，均以客户端视角显示。累计量来自核心，包含 TCP 和 UDP，自核心启动或被其他工具清零起累计；首次采样速率为零。
- TCP 请求的 IP 或域名、端口、核心嗅探到的域名、状态、流量、开始时间、最后活动时间和时长，时间使用服务器本地时区。
- 本次面板首次观察到该 IP 在线的时间。这不是精确的登录时间；关闭面板后会丢失。

终端较窄时内容自动换行，使用 `j/k` 滚动查看。没有终端时自动输出一次快照。退出面板不会关闭按 IP 统计，核心仍继续累计流量。

## 数据范围

来源 IP 是 Hysteria 服务端看到的客户端地址。同一 NAT、公用出口或中继后的设备可能共享一个 IP，不能据此区分每台物理设备。IP 改变后，统计可能要等客户端重连才使用新 IP。

核心 `/dump/streams` 仅提供 TCP 明细，UDP 只计入总流量。面板轮询可能漏掉两次刷新之间已结束的短连接；已结束记录显示最后一次采样到的流量，不能作为完整访问审计或精确计费依据。面板在内存中保留最多 500 条最近采样记录，退出即清除，不写入访问记录文件。

请求地址可能是域名，也可能只有 IP；“嗅探域名”只有核心启用嗅探且识别成功时才有值。它不是解析后的目标 IP。面板不会为域名额外做 DNS 查询，不展示 HTTPS 的完整 URL、路径或页面内容，ECH 等加密场景可能无法获知域名。

## 实现与兼容性

核心的 password 认证会把所有客户端合并为 `user`，无法区分不同 IP。因此启用时，脚本改用 Hysteria 官方支持的 command 认证，并安装权限为 `0700` 的本地 `bin/monitor-auth`：继续校验配置中的原密码，成功后返回 `hihy-ip:<来源IP>` 作为统计标识。原 `auth.password` 保留，客户端和配置导出无需改动。已有自定义 HTTP、userpass 或 command 认证不会被覆盖。

启用/关闭需要修改配置时会重启当前运行的服务，断开现有连接并重置核心统计；重复执行且配置已经满足要求时不会重启。修改失败会恢复旧配置及服务状态；重启失败且恢复不完整时会保留备份并提示。重新配置服务端会保留已启用的按 IP 认证。

监控读取实际配置中的 `trafficStats.listen` 和 `trafficStats.secret`，仅连接本机接口，禁用环境 HTTP 代理和重定向，不调用清零或踢人接口。没有配置统计接口时，启用功能会生成回环监听地址和随机密钥。接口不可用时显示错误并重试，单次快照模式返回非零状态。其他使用统计 ID 的工具需要适配 `hihy-ip:` 标识。

## 旧安装迁移（1.0.25）

更新脚本后执行 `hihy monitor secure`，将 API 限制为 `127.0.0.1` 监听，并替换为空或与代理密码相同的管理密钥。独立密钥不会导出到客户端配置；已有独立密钥会保留。此命令不切换认证方式，HTTP、userpass、自定义 command 认证也可以使用。启用按 IP 监控和完整重配置会执行同样的 API 配置检查。

需要修改时，正在运行的服务会重启一次；停止的服务不会启动。重复迁移不会轮换已独立的密钥或重复重启。菜单 13、`monitor --once` 继续只读，不会自动修改配置。SSH 登录后直接使用这些命令，无需开放统计端口或配置远程管理。

回环监听仍可能被代理用户通过隧道访问，因此管理权限依靠独立密钥隔离；代理密码不能授权统计清零或踢人操作。
